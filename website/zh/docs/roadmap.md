# 路线图

LytgOS2 的开发理念很简单：**慢就是快，克制且聚焦**。先把单机运行时内核做扎实、真正可用，再在它之上逐步生长出分布式能力，每一步都通过真实使用验证。

路线图分为三个阶段，以及一组横向能力。

## 阶段一 — 单机运行时内核（当前）

第一阶段让一个节点真正能够运行和管理一群 Agent：

- **五大核心能力**——LLM 接入、自实现 ReAct 循环、记忆、工具体系、REST 服务。
- **配置即 Agent**——一个包含 `AGENT.md` 的目录就是一个 Agent，不需要写后端代码。
- **多 Agent 并存**——同一实例上运行多个独立 Agent。
- **MCP 接入**——零代码接入社区 MCP server。
- **REST API**——通过 HTTP 暴露能力，任何语言都可集成。
- **私有部署**——单 JAR 装在企业自己的 K8s、虚拟机或物理机上，数据不出域。
- **审计 day one**——从第一版起写入 `tool_invocations` 和 `llm_calls`。

**边界**：这是可用的单机 Agent 运行时内核，不是完整的企业 Control Plane。

## 阶段二 — 底座分布式（规划）

让运行时可以水平扩展：

- 实例无状态化：LytgOS2 进程内不保留本地状态。
- 状态外置：Session、记忆和审计数据存储在实例之外。
- 多副本部署：多个实例运行在负载均衡后面。
- 高可用：消除单点故障。
- 支撑更大规模的 Agent 运行与管理。

## 阶段三 — 跨节点 Agent 协作（愿景）

在稳定的运行时语义之上支持跨节点 Agent 协作：

- 引入 Agent 通信底座，对接 A2A。
- 跨节点 Agent 发现与委托。
- 可靠异步协同，消息不丢不重。
- 让多节点上的 Agent 像一支团队。

## 横向能力

这些能力伴随各阶段逐步补齐，而不是一次性大版本交付：

| 能力 | 方向 |
| --- | --- |
| 多租户 | 组织/团队隔离与 ACL |
| SSO / 认证 | OIDC 与企业身份系统集成 |
| 完整审计 | 审计查询、导出与 SIEM 集成 |
| Tool Policy 与 RBAC | 按 Agent 的 Tool 权限与策略边界 |
| 可观测性 | 指标、链路追踪与运行看板 |
| Web 管理 | Agent、会话、定时任务与运行时管理 |
| 分布式状态 | 外置 Session、记忆和审计存储 |

## 开发原则

- **单机先行**——先证明运行时内核，再谈分布式。
- **真实使用优先于架构图**——每个阶段都用实际使用验证。
- **克制**——保持内核小；只在证据要求时增加治理与分布式基础设施。
- **私有优先**——数据留在企业自己的基础设施里，每一个动作都可审计。
