# CI 与本地钩子

## 1. GitHub Actions

工作流：`.github/workflows/ci.yml`。

| Job | 触发 | 内容 | 是否阻断 |
|---|---|---|---|
| `changes` | push / PR | 判断是否只改文档/提示词等非业务文件，输出 `code` 供其他 job 跳过重检查 | 否 |
| `verify` | push / PR | `./mvnw verify`，上传测试与质量报告 | 是 |
| `p3c` | push / PR | 阿里巴巴 Java 开发规约（P3C）门禁，上传 `pmd.xml`；分析错误或违规阻断 | 是 |
| `secrets` | push / PR | gitleaks 全历史扫描 | 是 |
| `dependency-review` | PR | 新增依赖漏洞/许可证审查 | 是 |
| `security` | 配了 `NVD_API_KEY` | Dependency-Check（缓存 NVD 数据） | 是 |
| `sbom` | push / PR | CycloneDX `target/classes/META-INF/sbom/application.cdx.json` | 是 |

分支保护当前要求 `verify`、`p3c`、`secrets`、`dependency-review`、`security`、`sbom` 六个检查。

纯文档、提示词、`.gitignore`、`specs/` 等不影响业务和架构的变更，`changes` job 会输出 `code=false`；`verify`、`p3c`、`security`、`sbom` 仍会创建并成功，但跳过 Maven 构建、P3C、Dependency-Check 和 SBOM。`secrets` 与 `dependency-review` 继续执行（耗时短，且文档也可能泄漏密钥）。

`changes` 把 Java、`pom.xml`、`src/`、`config/`、工作流、`mvnw`、`application*.yaml`、`logback*.xml` 视为代码变更；其余视为文档类变更。

`security` job 使用 `actions/cache` 缓存 `~/.m2/repository/org/owasp/dependency-check-data`，按 ISO 周滚动；每周首次运行恢复上一周数据库并只拉增量。

## 2. 本地钩子

仓库提供 `.githooks/pre-commit`，只跑快速检查：

- `spotless:check`
- 如果安装了 `gitleaks`，跑 `gitleaks protect --staged`

启用：

```bash
chmod +x .githooks/pre-commit   # Linux/macOS/Git Bash
git config core.hooksPath .githooks
```

Windows Git Bash 同样适用。`gitleaks` 未安装时钩子只提示并跳过，不阻断本地提交；CI 仍会扫描。

## 3. 命令

```bash
# CI 同款
./mvnw -B -ntp verify

# 安全扫描（需要 NVD_API_KEY）
NVD_API_KEY=... ./mvnw -B -ntp -Psecurity verify

# 只生成 SBOM
./mvnw -B -ntp -Psecurity -Ddependency-check.skip=true verify -DskipTests

# 本地 P3C 阻断门禁
./mvnw -B -ntp -Pp3c verify
```

## 4. 失败处理

1. 先看 `target/surefire-reports`、`target/pmd.xml`、`target/spotbugsXml.xml`。
2. 格式问题跑 `./mvnw spotless:apply`，不要手工调格式。
3. 规则误报加窄范围 suppression，并在 PR 说明原因。
4. 依赖漏洞优先升级；不能升级时记录风险、影响范围和缓解措施。
5. 不允许用 `-DskipTests`、`-Dpmd.skip=true` 等方式绕过主分支门禁。
