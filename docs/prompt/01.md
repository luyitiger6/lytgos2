# 项目启动提示词提炼

> 来源：LytgOS2 项目窗口。以下提示词按阶段提炼，可直接复用；`[方括号]` 为需要替换的占位符。
>
> 使用方式：从第 1 阶段顺序推进；每个阶段完成后先验收，再进入下一阶段。

---

## 1. 可复用提示词

### 1.1 理解项目文档

```text
请阅读 [项目目录] 下的 [文档列表]，提炼：
1. 项目是什么、目标用户和核心价值
2. 1.0 交付范围与后续扩展边界
3. 架构分层、核心模块和关键流程
4. 文档之间的口径冲突和未决事项
5. 建议的实施顺序和首批可演示成果

只做理解，不修改文件。
```

### 1.2 重写项目理解

```text
基于上述文档，按「产品定位 → 1.0 范围 → 架构 → 核心机制 → 实施与验收」重写一版项目理解。

要求：
- 以最新技术方案为权威，需求文档作为验收下限
- 标出所有冲突，不要自行替项目做未确认的决策
- 明确当前是设计阶段、骨架阶段还是已实现阶段
```

### 1.3 确认产品命名

```text
产品名确定为 [产品名]，CLI 命令为 [CLI 名]。

请把文档中的旧占位名、命令、工作区路径、数据库名、Maven 模块名统一为：
- 产品名：[产品名]
- CLI：[CLI 名]
- 工作区：[.xxx/]
- 数据库：[.xxx/xxx.db]
- Maven 模块：[prefix-*]
- 版本：[产品名 1.0]

同时修复粘连的旧 token，保持正文内容不变。
```

### 1.4 整理 Markdown 格式

```text
整理 [docs 目录] 下所有 Markdown 文档的格式：
- H1/H2/H3 统一编号，补齐无编号章节
- 代码块加语言标记
- 表格分隔行统一为 | --- | --- |
- 产品名与中文之间补空格，清除旧占位名
- 去除行尾空格，保持 UTF-8 无 BOM，文件末尾保留换行

不要改写正文内容；完成后输出每份文档的校验结果。
```

### 1.5 生成 CLAUDE.md

```text
根据项目文档和当前仓库状态，在根目录生成 CLAUDE.md，使用中文，包含：
1. 项目概述与当前状态
2. 权威文档及优先级
3. 命名规范
4. 目标技术栈
5. 架构与核心模块
6. 不可协商的设计规则
7. 已验证的构建/运行命令
8. 实施顺序和工作约定

不要虚构未实现的能力；明确标注骨架阶段、TODO 和扩展边界。
```

### 1.6 生成 1.0 基线

```text
生成 [docs/ReleaseBaseline.md]，作为 1.0 的唯一口径基线。至少包含：
- 产品身份与命名
- 1.0 必须交付 / 明确不做
- 模块清单与扩展模块
- 核心机制约束
- 数据表、Tool、CLI、REST 端点清单
- 验收指标和 Demo
- 文档冲突裁决表
- 实施顺序

遇到文档冲突时给出明确裁决和理由，不要留下模糊项。
```

### 1.7 生成标准开源 README

```text
参考标准开源项目 README，在根目录生成/重写 README.md，使用中文。包含：
- 顶部居中的 Logo、标题、Slogan、徽章
- 项目简介和与相邻概念的对比
- 核心特性
- 架构图
- 快速开始与使用示例
- 配置、项目结构、兼容性
- 文档索引、路线图、安全说明
- 参与贡献、许可证、致谢

明确标注当前处于骨架阶段、哪些命令尚不可用。
```

### 1.8 校验文档一致性

```text
对比 CLAUDE.md 与 README.md：
1. 列出两份文档中的硬性数字、命名、范围、安全边界
2. 判断是否一致
3. 列出仅详略不同、不构成冲突的部分
4. 补齐真正的覆盖缺口，保持各自定位

输出对比表和修改结果。
```

### 1.9 生成架构图

```text
为 README 生成架构图，使用 SVG（或 PNG），放到 [docs/images/] 并嵌入 README 的架构章节。

要求：
- 展示接入层、引擎层、能力层、基础层
- 展示 CLI / Web / Scheduler 三个触发源
- 标注 1.0 范围与扩展阶段边界
- 深色背景、清晰可读、可点击查看大图

完成后校验 SVG/XML 并渲染预览。
```

### 1.10 生成 Logo 并居中标题

```text
为 [产品名] 生成一个炫酷的 SVG Logo，放到 [docs/images/logo.svg]：
- 深色圆角方形底 + 科技纹理
- 渐变主字母或抽象符号
- 轨道、节点或版本徽章
- 发光、星芒等细节

同时把 README 顶部的 Logo、标题、Slogan、徽章居中显示，并把架构图也居中。
```

### 1.11 Maven 多模块初始化

```text
用 Maven 初始化这个项目：
- 根项目 packaging=pom
- 按 [模块清单] 创建多模块
- JDK 21，Spring Boot 3.x
- 每个模块创建最小可编译代码
- 配置 spring-boot-maven-plugin，boot 模块生成可执行 fat JAR
- 执行 mvn clean package 并确保 BUILD SUCCESS
- 启动 boot JAR，验证 health 端点
```

### 1.12 清理根项目源码

```text
根项目应该是 POM 聚合项目，不需要源码。

删除根目录 src/ 和占位 Main.java，更新 IDE 模块配置，确保源码只存在于各子模块。
修改后重新执行 mvn clean package 验证。
```

### 1.13 设置默认 JDK

```text
把本机 Maven 默认 JDK 改为 21：
- 设置用户级 JAVA_HOME
- 验证 mvn -v 显示 JDK 21
- 说明当前已打开终端/IDE 需要重启
- 不要修改系统级 PATH（除非明确要求）
```

### 1.14 验证 boot 入口

```text
验证 [boot 模块] 是否能运行，并说明它是否有 main 函数。

解释 [boot 模块] 与 [cli 模块] 两个入口的分工：
- 哪个是 Spring Boot 可执行入口
- 哪个是 Picocli CLI 骨架
- 哪个还没打成可执行 jar

实际启动 boot JAR 并检查 health 端点。
```

### 1.15 记录后续改造建议

```text
把「CLI/boot 入口改造」的两个方案记入项目记忆，标记为以后改造用，现在不要实现：
1. 保留双入口，把 CLI 打成可执行 jar
2. 做统一启动器，按 chat/serve/gateway 分派
```

### 1.16 提炼提示词

```text
把我在这个窗口里的提示词提炼成一份可复用的提示词文档，写入 [docs/prompt/01.md]。
按阶段组织，保留原始提示词顺序，使用 [方括号] 占位符方便复用。
```

## 2. 本窗口原始提示词顺序

1. 理解这个项目的四份文档。
2. 重新理解四份文档，按产品、范围、架构、实施重写。
3. 确认产品名和 CLI 名：`LytgOS2` / `lytgos`。
4. 整理四份文档格式，整理成好看的格式。
5. 确认四份文档是否都格式化完成。
6. 根据这些信息生成 `CLAUDE.md`。
7. 先产出 `docs/ReleaseBaseline.md`。
8. 基于这些信息生成 README。
9. 后续思考过程用中文，README 参考标准开源项目输出。
10. `CLAUDE.md` 用中文表示。
11. 对比 `CLAUDE.md` 和 `README.md` 内容是否一致。
12. 对齐两份文档的覆盖缺口。
13. 为 README 生成 SVG/PNG 架构图，放到 `docs/images/` 并嵌入 README。
14. 用 Maven 初始化项目，按文档模块拆分，并确保能编译打包。
15. 删除根目录源码，根项目改为 POM 聚合项目。
16. 把本机默认 JDK 改为 21。
17. 把项目与所有模块调整为 21。
18. 将 README 标题居中，并生成炫酷的 Logo。
19. 验证 boot 是否能运行，确认 main 函数和入口分工。
20. 把入口改造建议保留到项目记忆，以后再用。
21. 提炼本窗口的提示词。
